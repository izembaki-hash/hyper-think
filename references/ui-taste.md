# User Interface & Visual Taste Reference

Load this file whenever the task involves creating or reviewing an interface, landing page, app screen, or visual styling.

---

## 1. Anti-Slop Visual Policy
Generic AI outputs consistently look the same: purple-to-cyan gradients, glowing dark meshes, centered hero text, three identical cards, and unnecessary floating orbs. Reach past these defaults deliberately.

- **Color Discipline**:
  - Avoid stereotypical AI neons (`#00f0ff`, `#7928ca`) and generic cyberpunk violet palettes.
  - Choose intentional, grounded color systems:
    - *Architectural Minimal*: Deep carbon (`#0f1012`), warm stone/slate, off-white bone (`#f4f3ef`), with a single functional accent (e.g., warm copper, amber, international Klein blue).
    - *Swiss Monospace*: High-contrast black and white with clear typographic grid hierarchy.
    - *Warm Editorial*: Muted parchment, deep ink, terracotta, forest tones.
- **Zero Emojis Policy**:
  - Emojis are strictly banned across all deliverables (UI buttons, titles, cards, technical dashboards, and conversational output) unless the user explicitly requests an emoji-centric interface or icon set.
  - Use crisp, minimal inline SVGs, geometric marks, or typographic indicators (`01`, `02`, `03`).
- **Strict Ban on AI Slop Badges, Floating Pills & Ping Dots**:
  - Never generate floating pill badges with pulsing/ping dots (e.g. elements with `animate-ping`, `bento-card mb-8 rounded-full` or fake agency status slogans like "متاحون لاستقبال مشاريع الربع القادم • تجارب رقمية تفوق الخيال" or "Available for Q3 projects").
  - Never generate self-referential vanity pills such as "Generated by AI", "Powered by Hyper-Think", or glowing robotic badges.
  - Interfaces must feel authentic, mature, and structural—handcrafted by senior human design engineers (Linear, Vercel, Apple, Stripe, Teenage Engineering), with clean, restrained headings and navigation.

## 2. Arabic & RTL Layout Engineering
Interfaces in Arabic require dedicated typographic and directional rigor, not just setting `dir="rtl"`:
- **Typographic Scale & Line-Height**:
  - Arabic script has taller ascenders and deeper descenders than Latin script. Standard Latin line-height (`1.2 - 1.4`) causes text collision in Arabic. Always use `line-height: 1.6` to `1.8` for Arabic body text, and `1.25` to `1.35` for headings.
  - Recommended font stacks: `-apple-system, BlinkMacSystemFont, 'Segoe UI', 'Cairo', 'IBM Plex Sans Arabic', sans-serif`.
- **CSS Logical Properties**:
  - Never use hardcoded directional properties like `margin-left`, `padding-right`, `left: 0`, or `float: right`.
  - Use logical properties: `margin-inline-start`, `margin-inline-end`, `padding-inline`, `inset-inline-start`.
- **Icon Mirroring**:
  - Directional icons (arrows, chevrons, progress meters, undo/redo) must be flipped in RTL (`transform: scaleX(-1)`).
  - Non-directional icons (search glass, clock, checkmark, audio waves) remain unmirrored.

## 3. UI States & Edge Cases
Never design solely for the "happy path" with ideal short data:
- **Empty States**: Design meaningful empty states with clear explanatory text and an immediate call to action.
- **Loading & Skeleton States**: Use subdued layout skeletons rather than jarring full-screen spinners.
- **Error States**: Display inline, actionable error messages with recovery options; never silent failure.
- **Extreme & Long Text**: Test with 3x longer text strings. Ensure text wraps gracefully or truncates with `text-overflow: ellipsis` without breaking card layouts or overflowing flex boundaries.

---

## 4. Accessibility & Contrast (WCAG AA/AAA)
- Ensure a minimum contrast ratio of 4.5:1 for normal body text and 3:1 for large headings against background colors.
- Always provide clear `:focus-visible` outline indicators for keyboard navigation.
- Use semantic HTML tags (`<nav>`, `<main>`, `<article>`, `<button>`) rather than `<div>` soup.
- Ensure all interactive icon buttons contain accessible `aria-label` descriptions.

---

## 5. Motion & Physics
- Easing curves: `cubic-bezier(0.16, 1, 0.3, 1)` represents `easeOutExpo` (high initial velocity with smooth deceleration).
- For true spring physics, use dynamic spring formulas, CSS `@keyframes` with computed damping, or physics engines.
- Always wrap non-essential motion in `@media (prefers-reduced-motion: reduce)` to respect user accessibility preferences.

---

## 6. Visual Verification with Browser Tools
If browser tools (Antigravity built-in browser, DevTools, or local preview servers) are available:
1. Serve the page locally (`python -m http.server` or dev server).
2. Open the page in the browser to visually audit layout, responsiveness, contrast, and alignment.
3. Test interactive states (hover, focus, click, audio/visual events).
4. Inspect the console to ensure zero JavaScript runtime exceptions.
